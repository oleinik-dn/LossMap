Ты — ведущий фронтенд-разработчик. Собери посадочную страницу lossmap.pro для команды LossMap: мы находим потери на пищевых производствах по данным и доводим их до денег.

1. `README.md` — цель, аудитория, структура блоков, цены, правила кейсов, дизайн-токены, анимации, стек, хостинг, требования к качеству. **Если что-то не сходится — прав README.** Если README чего-то не говорит — спроси меня, не придумывай.
2. `docs/design/hero-b-reference.html` — эталон первого экрана (вариант B, тёмный). Это разметка с inline-стилями из дизайн-инструмента: служебные теги `<x-dc>`, `<helmet>` и скрипт `support.js` не переноси. Перенеси композицию, тексты, цвета, отступы и анимации в компоненты Astro.
3. `legacy/` (если папка есть) — исходники старого сайта oeeru.netlify.app. Из него можно взять логику интерактивной схемы смены 480 минут и тексты FAQ, но стиль и позиционирование — только из README.

## Жёсткие правила

- **Никаких выдуманных цифр, отзывов, логотипов клиентов, имён.** Нет данных — ставь заметный плейсхолдер `[ВСТАВИТЬ: что именно]` и добавляй пункт в `TODO.md`.
- Кейсы — только обезличенные, по §5 README. Рубли не показывать.
- Все тексты, цены, кейсы и контакты — в `src/content/ru/*` (JSON или Markdown), не в разметке компонентов. Я должен править тексты без кода.
- Никаких отслеживающих cookies, внешних шрифтов, Google Analytics, iframe Cal.com. Шрифты — woff2 в `public/fonts`, только нужные начертания, кириллица + латиница.
- Отдельной формы заявки и серверного эндпоинта **нет**. Конверсия: ссылка на Cal.com + кнопки WhatsApp и Telegram + email.
- Без UI-фреймворков (React, Vue, Tailwind). Astro + чистый CSS с переменными из README + небольшие TS-скрипты.
- Цвета: янтарный только для потерь, бирюзовый только для найденных денег и главного действия.
- Анимации только SVG/CSS (`transform`, `opacity`), запуск через `IntersectionObserver` один раз, полное уважение `prefers-reduced-motion`.
- Не трогай сервер, DNS и секреты. Деплой не запускай — только подготовь конфиги и скрипт.
- Коммит после каждого этапа, понятное сообщение на русском.

## Этапы

Перед началом: прочитай README и эталон, задай мне до 5 вопросов, если что-то блокирует работу, и покажи план. Жди моего «ок».

**Этап 1. Каркас.** Astro (static), `src/styles/tokens.css` с токенами из README, базовые стили, шрифты локально, точечная сетка фона, контейнер, `Header`, `Footer`, `src/content/ru/site.json` (контакты, ссылки Cal.com/WhatsApp/Telegram с плейсхолдерами). `npm run build` без ошибок.

**Этап 2. Первый экран.** `Hero` + `ParetoChart` + плитки OEE / потери / € и `ResultsStrip` — 1:1 с эталоном. Анимации: полосы Парето, пульс «live», счётчики (`tabular-nums`). Адаптив до 360 px: H1 36 px, колонки складываются.

**Этап 3. Остальные блоки** в порядке таблицы §3 README: `ShiftLosses` (схема 480 минут), `Services`, `Process`, `Cases`, `ExampleReport`, `Demo`, `Team`, `Pricing`, `Faq`, `FinalCta`. Цены и условия экспресс-разбора — ровно из §4.

**Этап 4. Калькулятор потерь** (`Calculator` + `src/scripts/calculator.ts`):
- Ввод: число линий, смен в сутки (1–3), рабочих дней в год (по умолчанию 300), номинальная выработка на линию, ед./час, маржа на единицу, €, текущий OEE, % (по умолчанию 60).
- Расчёт: `доп. маржа/год = линии × смены × 8 × дни × выработка × маржа × ΔOEE`, где ΔOEE = 5 п. п. (нижняя граница) и 10 п. п. (верхняя).
- Вывод: диапазон «€ X – Y в год», под ним открытая формула и пометка «оценка, точная цифра — по вашим данным». Кнопка «Разобрать на моих данных» → Cal.com.
- Валидация ввода, без перезагрузки страницы, пересчёт на лету, корректно на телефоне.
- Юнит-тесты на формулу (Vitest).

**Этап 5. UTM и ссылки.** `src/scripts/utm.ts`: берёт `utm_*` из адреса страницы, хранит в `sessionStorage`, дописывает к ссылкам Cal.com; в первое сообщение WhatsApp/Telegram добавляет короткую метку источника. Кнопка записи — в шапке, на первом экране, после калькулятора, после цен и в финальном блоке.

**Этап 6. SEO, доступность, скорость.** `<title>`, description, Open Graph (`public/og-image.png` 1200×630 — сделай простую тёмную картинку с логотипом и заголовком), `sitemap.xml`, `robots.txt`, schema.org `ProfessionalService`, `hreflang` (sr — заготовка), страница `privacy` по §7 README (аналитика без cookies, Cal.com, WhatsApp, Telegram; плейсхолдеры для реквизитов). Цели: Lighthouse mobile Performance ≥ 95, Accessibility ≥ 95, SEO 100, вес без шрифтов ≤ 200 КБ. Прогони Lighthouse локально и приложи цифры.

**Этап 7. Деплой-конфиги** в `deploy/`:
- `docker-compose.yml`: Caddy (отдаёт `/opt/lossmap/site`) + Umami с PostgreSQL на поддомене `stats.lossmap.pro`.
- `Caddyfile`: lossmap.pro и www → редирект на lossmap.pro, HTTPS, gzip/zstd, кэш статики (`immutable` для хэшированных файлов), заголовки безопасности (CSP без сторонних источников, кроме Umami на своём поддомене), `404.html`.
- `deploy.sh`: `npm ci && npm run build && rsync -avz --delete dist/ $DEPLOY_USER@$DEPLOY_HOST:/opt/lossmap/site/`.
- `.env.example` без реальных значений.
- `docs/deploy.md`: пошагово для меня — подготовка сервера (Docker, пользователь, firewall 80/443), DNS-записи в Cloudflare, первый запуск, обновление, откат, как подключить Umami-скрипт.
- Опционально: `.github/workflows/deploy.yml` (сборка + rsync по SSH-ключу из секретов), выключен по умолчанию.
